# Прямое меню Telegram: эксперимент 0.9.0-rc.1

Команда `/bitrix` открывает отдельное меню плагина без вызова модели, если Ива поддерживает
предлагаемый API `extensions.sh.iva.telegramScreen`. Переходы заменяют одну страницу,
кнопка «Закрыть» убирает действия. Главное меню Ивы не меняется.

Это экспериментальная зависимость: штатная Ива 0.4.11 такого API не содержит.
На ней попросите «Покажи настройки Битрикс»: прежний `bitrix24_settings` и skill работают
как раньше, с отдельным ответом после каждого перехода. Версия Ивы сама по себе не доказывает
поддержку экспериментального API.

Манифест ссылается на `bitrix24_screen` существующего stdio MCP `bitrix24`. Обработчик
принимает `{event}` и возвращает `{type: "show", view: {markdown, rows}}` или
`{type: "close", markdown}`. Идентификаторы действий — прежние `b24s:...` с проверкой
revision, offer token и срока действия. Выбор режима сначала показывает подтверждение;
только следующая кнопка применяет настройку. Кнопка закрытия не применяет предложение.

Ива владеет callback-идентификаторами и сообщением, проверяет личный чат, владельца,
включение/доверие плагина, версию его содержимого, срок страницы и её ревизию. Плагин
не получает токен Telegram или ID чужих сообщений. Bridge использует отдельный unary
маршрут MCP proxy, который не закрывает текущую MCP-сессию агента.

После успешного действия повторная доставка нажатия может повторить только редактирование
страницы. При неизвестном результате или перезапуске во время действия экран требуется
открыть заново. Плагин сохраняет собственные проверки настроек и подтверждения задач;
API экранов не заменяет их и не служит изолированным сервисом авторизации для MCP tools.

После возврата на штатную Иву используйте запрос через skill. Настройки имеют прежнюю
schema1 и сохраняются; квитанции задач и проверки schema5 не менялись. Старые callback
экраны не становятся обычными сообщениями модели.

Очистка нативного `ask_question` из issue #272 — отдельное изменение Ивы/Eve. Она
не реализуется вызовом `bitrix24_screen` и не означает успех действия на портале.
