# ADR-0001: read-only доступ через изолированный stdio MCP-процесс

Статус: принято для первой версии

Дата: 25 августа 2026 года

## Контекст

Интеграция должна быть полностью подключаемой, не менять ядро Ивы, переживать обновления и
подходить разным владельцам Iva. Секрет входящего webhook Bitrix24 не должен находиться в
репозитории или общем окружении агента.

Рассматривались eve Extension, удалённый MCP на Cloudflare Worker и локальный stdio MCP.

## Решение

Первая версия будет Agent Plugin с skill и stdio MCP-сервером. Ива поднимет сервер через свой
MCP proxy. Сервер обращается к Bitrix24 напрямую по HTTPS и публикует только конкретные
read-only инструменты.

Worker не входит в архитектуру текущего исходящего чтения.

## Последствия

Положительные:

- нет изменений ядра и расширения внутри процесса eve;
- секрет изолирован в env конкретного MCP-процесса;
- один публичный плагин подходит разным порталам;
- нет обязательного внешнего backend;
- отказ процесса плагина не должен останавливать Иву.

Цена решения:

- MCP-сервер должен поставляться самодостаточным bundle;
- Linux-инсталляции используют systemd-рельсы Ивы;
- нужно тестировать совместимость bundle с версией Node.js, поддерживаемой Ивой;

## Инварианты

- Нет инструмента произвольного REST-вызова.
- Имя REST-метода всегда выбирает код, а не модель.
- Секрет никогда не передаётся аргументом MCP.
- Изменяющие методы отсутствуют в allowlist и тестируются отрицательно.
- Публичная версия не содержит адресов или данных частного портала.
