# Настройки через Panels

Предварительная 0.9.0-rc.2 поддерживает общий контракт `iva-panels/v2`.
Включённый и trusted Bitrix24 автоматически получает кнопку «Настройки» в карточке
`/panels`, если в Panels разрешён `dynamicPanels`. Требуется Panels 0.2.0-dev.1
или версия с тем же контрактом. Штатное меню Bitrix24 продолжает работать самостоятельно.

Доступны режим чтения/записи с подтверждением, загрузка, удаление сообщений и файлов,
поля сотрудников и email. Выбор показывает текущее и предложенное состояние;
только подтверждение сохраняет настройку. Отмена ничего не меняет. Настройки
не увеличивают права webhook и не очищают уже полученные сообщения или память Ивы.
Проверка подключения и прав остаётся в обычном меню Bitrix24.

## Установка и транспорт

При обновлении Ива устанавливает descriptor `panels.json` и отдельную службу
`sh.iva/services/panels`. Нужны Linux, Node 24, `bash` и `flock`; Ива сама управляет
службой при включении и выключении плагина. Запрошенный служебный порт 8736 нужен
только для `/health` на loopback; используется назначенный Ивой `IVA_SERVICE_PORT`.
API не открыт на TCP: HTTP POST `/panels/v1` обслуживается только через
`PLUGIN_DATA/panels.sock`, права 0600. Приватный каталог должен иметь канонический
путь без symlink. Unix socket не изолирует доверенные процессы одного пользователя.
Сервис не использует Telegram credentials, MCP session или методы Bitrix REST.
Он читает только собственный bitrix24-read.env из data/custom/plugins: обычный
Node parseEnv, без shell, файл 0600 того же UID без symlink. Из него берутся только
webhook для identity и marker исходной policy. Секрет не передаётся Panels. После
замены env нужно перезапустить MCP Bitrix24 и эту службу.

Плагин проверяет строгий envelope, identity/version, operation и допустимые значения.
До 4 КиБ запроса, 32 КиБ ответа, закрытый набор страниц/действий, без произвольных
путей, команд и аргументов. `read` и `status` только читают.

## Настройки и подтверждения

Оба интерфейса используют прежний `settings.json`, revision и общую блокировку
`task-writes/lock`. Нет второго файла с независимыми рабочими настройками.
Prepare сохраняет предложение `panels-offers/<token>.json` (0600), срок десять минут.
В один момент может быть одно действующее предложение Panels. Обычное меню может
создать своё предложение, но сохранение через любой интерфейс изменяет revision:
остальные предложения устаревают и не могут изменить настройки.

Confirm сохраняет policy, revision + 1 и терминальную квитанцию в одной атомарной
записи с fsync. Прежнее превью задачи становится недействительным, как в обычном меню.
Квитанции сохраняются при последующих изменениях, включая MCP, и не попадают в ответы
MCP или текст экрана. Повтор confirm/cancel возвращает прежний терминальный результат.
Отмена сохраняется отдельно; stale revision даёт отменённый результат.
Истёкшее предложение или другая identity отменяются с записью квитанции при
следующем изменяющем запросе либо службой при старте и каждые 15 секунд.
Status не записывает файлы и не повторяет эффект. Потерянный ответ проверяется кнопкой
Panels «Проверить результат». Если сохранилось только предложение, нужно дождаться
его истечения и снова проверить результат; автоматически подтверждать нельзя.

Журнал сохраняет до 1000 предложений, затем новые отклоняются до проверки оператора.
Нельзя удалять незавершённые предложения или журнал Panels ради повторной записи.
Нельзя редактировать policy вручную без корректного увеличения revision.
Смена подключения требует нового предложения; старые подтверждения привязаны к порталу
и пользователю без сохранения webhook secret.

После первого подтверждения через v2 в settings.json появляются квитанции.
Версия 0.9.0-rc.1 не понимает это дополнительное поле и отказывает с SETTINGS_INVALID.
Откат к ней требует операторской сверки и миграции, без восстановления старого policy
или удаления доказательств. Для временного отключения интеграции выключите dynamicPanels
в Panels; обычное меню текущей версии продолжит работать.

## Для разработчика и Ивы

Контракт объявлен в plugin/panels.json. Реализация в server/src/panels-api.ts,
transport в panels-main.ts. Настройки принадлежат Bitrix24; Panels знает только общий
протокол. Используйте установленный skill `iva-panels-integration` и его CONTRACT.md
для других плагинов. Bitrix24 не импортирует код Panels, не требует его при запуске
и не меняет ядро Ивы.

Автотесты проверяют сохранение/отмену, повтор и restart, CAS между интерфейсами,
общую блокировку, истечение, identity/version, чистый status, приватный socket
и MCP discovery. Живые Telegram-нажатия нового API проверяются отдельно после установки.
