# Changelog

Значимые пользовательские изменения этого проекта будут фиксироваться здесь.

## Unreleased

- По результатам production canary защитное окно между принятием update-job и первым
  рестартом MCP увеличено до 30 секунд, чтобы дать доставленному ответу больше времени на
  полное завершение хода до замены соединения через `iva plugin update`.
- Проверка подключения больше не должна дополняться чтением списка и добровольной выдачей
  рабочих задач. Пустой результат просроченных описывается без догадок о других дедлайнах и
  без подмешивания ближайших задач.

- Подготовлен read-contract `0.3.0-rc.3`: добавлен однозначный режим `overdueOnly` по
  официальному фильтру Bitrix24 с отметкой `asOf`.
- Задачи и события истории без корректного ограниченного ID больше не считаются валидными;
  `get_task` проверяет совпадение возвращённого и запрошенного ID, а профиль webhook обязан
  содержать безопасный положительный ID.
- Типы событий истории ограничены документированным allowlist, отчество исполнителя события
  удалено как лишнее поле, а неоднозначный task error `0` нормализован без чтения и отражения
  сырого описания.

- Исправлен найденный живой проверкой update lifecycle: tool явно подключается к user-systemd
  bus, запускает worker без блокировки и оставляет время на доставку ответа перед рестартом.
- Worker больше не выбирает `iva` через унаследованный `PATH`, а вызывает штатный
  `~/.local/bin/iva`; это исключает попадание в root/sudo wrapper и самоуничтожение updater,
  запущенного дочерним процессом основной `iva.service`.
- Skill запрещает shell/systemd fallback после ошибки update-tool; status различает зависшую
  очередь, устаревший результат job и фактический более новый SHA плагина.

- Подготовлен read-contract `0.3.0-rc.1`: строгие типы ID и дат, стабильные названия статусов,
  приоритетов и оценок, а также nullable-имена автора, ответственного и группы без новых REST
  scopes.
- Исправлен фильтр состояния задач: используется официальный `REAL_STATUS` со значениями
  2–6 вместо служебного `STATUS`; skill и документация синхронизированы.
- Повреждённые элементы отмечаются как частичный результат, повреждённая оболочка ответа
  больше не выглядит пустым списком, некорректные диапазоны дедлайнов отклоняются, а upstream
  error-коды проходят безопасную нормализацию.
- Метаданные полей ограничены только полями публичного task-контракта; добавлена матрица
  совместимости и подробное описание схемы.

## 0.2.0 — 2026-09-06

- Добавлены безопасная проверка обновления из записанного GitHub-источника, явное
  подтверждение точного SHA, фоновый systemd worker, статус, `iva doctor` и автоматическая
  попытка возврата предыдущего SHA при провале диагностики.
- Публичное описание проекта отделяет общую интеграцию Bitrix24 для Iva от read-only статуса
  текущего выпуска; синхронизированы README, package metadata и GitHub About/topics.
- Добавлен русскоязычный установщик одной командой: штатная установка через Iva, скрытый
  ввод и проверка webhook, атомарный env `0600`, явный trust, диагностика и переход в Telegram.
- Установщик и skill различают REST scope и права пользователя и дают точный путь исправления
  `insufficient_scope` для права «Задачи» без рекомендации включать доступ ко всему порталу.
- Репозиторий подготовлен к открытой разработке: MIT License, публичная документация,
  contribution/security policies и расширенный secret scan.
- Добавлено ограниченное read-only чтение истории задачи через `bitrix24_task_history`;
  используется существующий scope `task`, логин автора события не возвращается.
- Нормализованные задачи содержат безопасную ссылку `webUrl` без webhook-секрета.
- Список задач сохраняет метаданные пагинации Bitrix24 и возвращает безопасный `nextStart`.
- Skill запрещает обход MCP через shell, чтение env плагина и прямые вызовы webhook.
- Уточнены правила работы со статусами задач и экономного чтения деталей.
- Совместимость подтверждена на Iva 0.4.0.

## 0.1.0 — 2026-08-25

- Первый read-only контур для задач Bitrix24.
- Четыре MCP-инструмента: проверка подключения, список задач, чтение задачи и метаданные
  полей.
- Закрытый allowlist REST-методов, ограничение ответов, retry, timeout и redaction.
