# Changelog

Значимые пользовательские изменения этого проекта будут фиксироваться здесь.

## 0.7.0-rc.5 — 2026-10-04 (предварительный выпуск)

- Компактное подтверждение: связанные поля и пункты идут подряд, пустые строки разделяют действия.
- Рабочая почта рядом с именем сотрудника, если доступна в аккаунте. Без права на почту
  сохраняется явный fallback; никаких угаданных адресов.
- Читаемые даты и время с сохранением исходного часового пояса и точного payload.
- Правки чек-листа показывают названия пунктов; номера нужны только при совпадении названий.
- Новый чек-лист получает явное название, пункты связаны с его корнем. Поддержаны выбор
  существующего списка и создание нового именованного списка; неизвестный результат не повторяется.
- Инструкции обычных ответов описывают компактное rich-представление чек-листа.
  Нативные подтверждения по-прежнему требуют отдельной поддержки rich на стороне Ивы.

## 0.7.0-rc.4 — 2026-10-04 (предварительный выпуск)

- Native approval cards use readable plain text without visible Markdown escapes or checklist JSON. Reports retain rich-replies instructions.
- A documented null success from checklist editing no longer stops a batch or forces separate approvals for each item.
- Reassignment attempts the confirmed change under Bitrix24 permissions without a local department hierarchy gate.
- Added project Kanban stage discovery and movement, distinct from task status.
- Added previewed deletion of a selected file or message in the current task chat; file removal is verified after the API response. All actions may share one batch confirmation.

## 0.7.0-rc.3 — 2026-10-04 (подготовка выпуска, ещё не выпущено)

- Проверка обновлений сохраняет весь prerelease-суффикс с дефисами и отклоняет
  числовые идентификаторы с ведущими нулями. Исправление покрыто регрессионными тестами.
- Компилятор проверяет неиспользуемые переменные и параметры; проверка поставки
  отклоняет случайные копии файлов и каталогов с числовыми суффиксами.
- Повреждённые записи задач учитываются в лимите поиска документов: один вызов
  больше не продолжает перебор страниц сверх заявленного бюджета.

## 0.7.0-rc.2 — 2026-10-04 (предварительный выпуск)

- Исправлена схема подготовки действий в MCP listTools: Ива видит поля создания, правки
  и пачки. Проверка строгого контракта сохранена; добавлен тест экспортируемой схемы.

## 0.7.0-rc.1 — 2026-10-04 (предварительный выпуск)

- Правка существующей задачи: название, описание, срок, участники, проект, приоритет и теги;
  добавление наблюдателей сохраняет остальных. Чек-лист дополняется, существующие пункты
  можно переименовать, отметить выполненными или вернуть в работу. Новая задача взамен не создаётся.
- Запрос из нескольких пунктов собирается в один черновик и одно подтверждение. Проверки
  всех пунктов предшествуют записи; сбой останавливает остаток и сохраняет точный прогресс.
- Создание сразу с комментарием и выбранными файлами входит в то же превью; отправка
  использует фактически созданную задачу, без второго подтверждения.
- Старое подключение без каталога вложений восстанавливает его из проверенной установки
  Ивы. Загрузка в чат проверяет ID файла и сообщения перед сообщением об успехе.
- Значение 0 для проекта/родителя означает отсутствие связи и больше не даёт ложное предупреждение.
- Сохраняется rich-оформление из локальной работы 0.6.1-rc.1. Повторная проверка состояния
  защищает ещё не изменённые задачи пачки от правок между preflight и записью.
  Новая live-проверка записи не выполнялась; stable остаётся 0.6.0.

## 0.6.1-rc.1 — 2026-10-04 (локальный предварительный выпуск)

- Инструкции Ивы используют rich replies для списков и отчётов: компактные таблицы,
  короткие ссылки на задачи, читаемые сроки и сворачиваемые подробности. Ответ после
  действия начинается с проверенного результата. Превью получает заголовок и выделенные
  названия полей; все значения видимы и экранированы от внедрения разметки.
- Обновление кнопок и статуса выбора требует исправления Telegram-канала Ивы;
  один плагин не управляет сообщениями native ask_question.

## 0.6.0 — 2026-10-04

- Действия с задачами вышли из RC в стабильный канал: создание, комментарии, файлы в чат
  задачи, завершение, доработка, смена ответственного и срока через превью и подтверждение.
- Владелец подтвердил создание и закрытие задачи в боевой работе на актуальной Иве Шимы.
  Точная установленная версия не зафиксирована. Другие операции покрыты автоматическими
  тестами, отдельная live-проверка для них не заявляется.
- Главная страница объясняет возможности через запросы в чате; добавлены две иллюстрации,
  навигация по помощи и промпты для изображений.
- Обычная установка и Marketplace используют stable 0.6.0. Для установок по точному RC-тегу
  описан переход на stable с сохранением настроек и квитанций.
- Серверный контракт действий, разрешения и граница подтверждения через модель сохранены.

## 0.6.0-rc.1 — 2026-10-04 (предварительный выпуск)

- Добавлен сценарий действий с задачами: создание с четырьмя обязательными полями,
  комментарий, файл в чат задачи, завершение, возврат на доработку, смена ответственного
  и срока. До записи Ива показывает полное превью и кнопки подтверждения/отмены;
  текстовая правка создаёт новое превью.
- Черновик живёт 30 минут и заменяет предыдущее превью владельца. Перед записью повторно
  проверяются состояние, права и подчинение текущего ответственного по руководителям
  подразделений. Файл ограничен каталогом вложений Ивы, 50 МиБ и подтверждённым содержимым.
- Запросы записи не повторяются автоматически. Квитанция сохраняется до сетевого вызова;
  частичный чек-лист и неопределённый результат возвращаются явно.
- Запись протестирована на синтетических данных; live-проверка портала и кнопок требуется
  перед переводом в stable. Передача ответа кнопки через модель не является криптографическим
  доказательством пользовательского согласия.

## 0.5.4 — 2026-09-30

  своей установки. Если на Ubuntu/Debian отсутствует LibreOffice и нужные пакеты доступны,
  она показывает команду для ручного запуска по SSH. Сам плагин пакеты не устанавливает.

## 0.5.3 — 2026-09-30

  и отдельную фоновую задачу. Функции и права доступа не изменены.

## 0.5.2 — 2026-09-30

- Описание skill теперь включает запросы на обновление плагина Bitrix24 и направляет Иву
  к кнопочному сценарию с отдельным фоновым worker. Skill прямо запрещает запускать
  обновление через собственный shell Ивы: такой процесс обрывался при её перезапуске.

## 0.5.1 — 2026-09-29

- Интерактивный установщик теперь предлагает установить LibreOffice без GUI на
  Ubuntu/Debian для разбора презентаций и страниц Office. Проверка и статус обновления
  сообщают, установлен ли пакет; обновление из Telegram не вызывает `sudo`.
- Обновлены транзитивные зависимости сборки после проверки уязвимостей; состав
  пользовательских функций не изменился.

## 0.5.0 — 2026-09-29

- Добавлены поиск и перечень файлов задач из прямых вложений, чата или комментариев и
  чек-листа; выбор файла учитывает контекст сообщения, автора и даты при наличии данных.
- Выбранный файл скачивается во вложения Iva для чтения и отправки в Telegram через
  `iva-file-delivery`; временная копия удаляется после успеха. Доступ и размер 50 МиБ
  проверяются повторно, подписанная ссылка не попадает в ответы MCP.
- Для PDF, Office и изображений доступен просмотр страницы; skill сначала разбирает текст
  документа и уточняет, нужен ли полный визуальный разбор, если пользователь не запросил
  его сразу. Обычный разбор задач завершается одним вопросом о найденных файлах.
- Поиск сотрудников использует документированные параметры `user.get`, что также
  обеспечивает корректный поиск файлов по задачам сотрудников подразделения.

## 0.4.1 — 2026-09-08

- Аналитика изменений задачи теперь сама читает task-chat вместе с нормализованной историей:
  системные события о смене исполнителя, проекта, сроков и статуса используются как данные,
  а пользователь больше не получает подсказку проверить чат вручную.
- Tool description и skill явно направляют модель к discussion при вопросах о причинах,
  решениях и последовательности изменений. Системные события остаются недоверенным текстом,
  чтение ограничено существующей пагинацией и не добавляет новых REST-методов или scopes.
- В стабильный выпуск вошли подготовленные в `0.4.1-rc.1` Marketplace, защита SemVer updater,
  полный distribution check и документированное решение пока не переходить на REST 3.0.

## 0.4.1-rc.1 — 2026-09-08

- Репозиторий публикует совместимый Marketplace Iva с отслеживаемым `stable`; плагин можно
  обнаружить и установить по имени штатным CLI без потери стабильных обновлений. `main`
  остаётся каналом release candidates.
- Проверка дистрибутива синхронизирует SemVer, manifest, Marketplace metadata и лимиты пакета
  Iva; CI теперь проверяет воспроизводимость всех трёх скомпилированных bundle-файлов.
- Updater не предлагает документационный commit с той же версией или ref, указывающий на
  более старую SemVer; изменение содержимого `plugin/` без version bump отклоняется проверкой.
- Для будущих GitHub Releases включена repository-level immutability; `v0.4.0` предшествует
  этой настройке, следующие выпуски будут публиковаться из draft после подготовки assets.
- Официальный REST 3.0 повторно оценён для текущего read-контракта. Runtime adapter намеренно
  не включён, пока task list не обеспечивает используемые фильтры по ответственному, статусу
  и срокам; существующий task-chat hybrid сохранён.

## 0.4.0 — 2026-09-08

- Карточка и статус обновления показывают SemVer установленной и кандидатной
  сборки вместо пары SHA. Версии читаются из manifest на точных проверенных commit, а полные
  SHA остаются внутренней границей подтверждения, установки и отката.
- Поиск сотрудников получил выборку по конкретному подразделению и может
  вернуть имя, фамилию, должность, подразделения и email профиля. Email доступен только со
  scope `user_basic` либо `user`; телефоны, фотографии и прочие поля не запрашиваются.
- Расширен read-контракт: добавлены обсуждение задач с поддержкой
  новой task-chat и legacy comments, проекты, сотрудники, подразделения, метаданные файлов,
  чек-листы и непосредственные связи задач.
- Добавлен `bitrix24_capabilities`: он показывает только относящиеся к плагину scopes и даёт
  точное объяснение прав для каждой функции. Базовое чтение с одним `task` не изменилось.
- Новые справочные tools требуют точного ID, строки поиска или родителя и имеют жёсткие
  лимиты. Телефоны и фотографии людей, download URL и содержимое файлов не возвращаются.
- Текст обсуждений, чек-листов и имена файлов явно считаются недоверенными данными; общий REST
  tool и рекурсивная выгрузка структуры портала отсутствуют.

## 0.3.0 — 2026-09-06

- Обновления из Telegram подтверждаются штатными кнопками Iva «⬆️ Обновить» и «Позже»:
  копировать SHA или фразу с телефона больше не требуется.
- Контур обновления ограничен записанным Git-источником этого плагина, полным SHA, зелёным
  GitHub Actions, свежим 15-минутным offer и одноразовым token. MCP не получает Telegram-токен.
- Фоновый worker запускается в отдельном user-systemd unit, переживает рестарт MCP, проверяет
  установленный SHA и `iva doctor`, а при отказе диагностики пытается вернуть прежнюю версию.
- Status различает успешное обновление, rollback, ошибку, зависшую очередь и результат,
  superseded более новым установленным SHA. Shell/systemd fallback из skill запрещён.
- Контракт чтения задач получил строгие ID и ISO-даты, стабильные названия статусов,
  приоритетов и оценок, безопасные имена участников и группы без дополнительных REST scopes.
- Добавлены однозначный `overdueOnly` с отметкой `asOf`, документированный фильтр
  `REAL_STATUS`, явные частичные результаты и безопасная нормализация ошибок Bitrix24.
- Проверка подключения больше не читает список задач, а пустой результат просроченных не
  дополняется догадками или ближайшими задачами.
- Production canary подтвердил кнопочный flow, фоновое обновление, последующий status,
  работоспособность MCP и диагностику Iva. Общее сообщение Iva об оборванном ходе после
  рестарта остаётся известным ограничением ядра и не определяет результат update-job.

## 0.2.0 — 2026-09-06

- Добавлены безопасная проверка обновления из записанного GitHub-источника, явное
  подтверждение точного SHA, фоновый systemd worker, статус, `iva doctor` и автоматическая
  попытка возврата предыдущего SHA при провале диагностики.
- Публичное описание проекта отделяет общую интеграцию Bitrix24 для Iva от read-only статуса
  текущего выпуска; синхронизированы README, package metadata и GitHub About/topics.
- Добавлен русскоязычный установщик одной командой: штатная установка через Iva, скрытый
  ввод и проверка webhook, атомарный env `0600`, явный trust, диагностика и переход в Telegram.
- Установщик и skill различают REST scope и права пользователя и дают точный путь исправления
  `insufficient_scope` для права «Задачи» без рекомендации включать доступ ко всему порталу.
- Репозиторий подготовлен к открытой разработке: MIT License, публичная документация,
  contribution/security policies и расширенный secret scan.
- Добавлено ограниченное read-only чтение истории задачи через `bitrix24_task_history`;
  используется существующий scope `task`, логин автора события не возвращается.
- Нормализованные задачи содержат безопасную ссылку `webUrl` без webhook-секрета.
- Список задач сохраняет метаданные пагинации Bitrix24 и возвращает безопасный `nextStart`.
- Skill запрещает обход MCP через shell, чтение env плагина и прямые вызовы webhook.
- Уточнены правила работы со статусами задач и экономного чтения деталей.
- Совместимость подтверждена на Iva 0.4.0.

## 0.1.0 — 2026-08-25

- Первый read-only контур для задач Bitrix24.
- Четыре MCP-инструмента: проверка подключения, список задач, чтение задачи и метаданные
